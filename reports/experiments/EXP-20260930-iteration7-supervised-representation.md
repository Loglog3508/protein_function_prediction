# 第七次迭代：监督表征与邻居扩展筛选

日期：2026-09-30。本文记录本地交叉验证与 CUDA 筛选结果，不代表竞赛平台成绩。

## 目标与验证口径

目标仍为严格五 seed 尾段 Macro F1 `> 0.5`。保留 `iteration4_tail` 的 1,062 条验证样本、五个 threshold seeds `17、31、42、73、101`，并保留第八轮实验 103 的 `0.338248` 作为 F1 优先回退基线。所有模型权重和运行目录只保留本地。

## 环境

- GPU：NVIDIA GeForce RTX 4060 Laptop GPU，8 GB
- PyTorch：`2.14.0+cu130`
- Transformers：`4.57.6`
- ESM-2 35M 和 150M 权重使用本地 Hugging Face 缓存，运行时配置缓存位置。
- Python 依赖使用项目虚拟环境，仓库配置不绑定本机解释器路径。

## 工程实现

新增 `src/train_esm_finetune.py`，支持：

- ESM residue windowing、special-token 排除和 mean/max pooling；
- 分类头、多标签 BCE/ASL、标签正类权重；
- 解冻最后 N 个 Transformer block；
- 按蛋白质聚合窗口分数；
- CUDA AMP、梯度累积、checkpoint 和 `validation_scores.npz` 输出。

单元测试与既有测试合计通过：`142 passed`；真实 CUDA smoke 运行成功，输出形状为 `4 × 500`。

## 结论

1. 继续增加 ESM 微调 epoch 或重复扩大模型规模，当前没有足够证据达到 0.5，暂不继续消耗 GPU。
2. 扩大局部对齐邻居数没有收益，说明瓶颈不是候选数量，而是标签迁移和特征融合方式。
3. 下一条结构性路线是将已有 120k 维 k-mer 特征与 ESM 960/1280 维嵌入直接拼接，训练同一个标签级 SGD/Logistic 模型；这与“分数后融合”不同，允许模型学习 ESM 表征对 k-mer motif 的条件补充。
4. 若联合特征在 100 个支持度分层标签上不能超过现有 k-mer 基线，则停止 ESM 路线，转向邻居级置信度门控和标签先验校准。
